# 3D models and data

Use 3D when depth is the idea: a surface, vectors in space, a real object turned to show another side, or an object cut open to show its inside. Keep the rest of the video flat; it reads faster.

## A 3D camera: `Episode3D`

Subclass `Episode3D` instead of `Episode`. `self.move_camera(phi=..., theta=...)` tilts and turns the camera while a line is spoken, `begin_ambient_camera_rotation()` orbits slowly, and `self.pin(...)` keeps a label flat on screen. The header and progress bar stay flat, and title, chapter and recap cards are never tilted. For a surface z = f(x, y), add the `surface-plot` block.

## Models from files

A model file goes in two ways. From Blender, export glTF 2.0 (`.glb`): it keeps the colours, the part names and the animations.

| | `mesh-model` block | `from_model` clip |
|---|---|---|
| Drawn by | manimvox's own lighting, one flat face per triangle | a 3D renderer, with real lighting and materials |
| Camera | Manim's: tilt, orbit, labels pinned beside it | its own orbit, set when the clip is made |
| Detail | simplified to at most 5000 faces | every triangle |
| Parts | `mesh_part` picks faces to recolour or label | none: the clip is one picture |
| glTF animations | no | yes, played in step with the clip |
| Extra | `trimesh` | `pyvista` |

```python
from blocks.mesh_model import mesh_model, mesh_part      # after `manimvox add mesh-model`
part = mesh_model("research/engine.glb", size=5)
valves = mesh_part(part, name="valve")                    # a glTF part by name

from manimvox.scenes import from_model
clip = from_model("research/engine.glb", seconds=6, orbit=360).loop()   # keeps turning under the narration
```

## Scans, simulations and cut-open views: `from_pyvista`

`from_pyvista(draw, seconds, setup=...)` renders any [PyVista](https://pyvista.org/) scene as a clip: `setup(plotter)` once, then `draw(plotter, t)` before each frame. Each frame is drawn from its own time, so a draft and a final render match. Inside `draw`, `screen_xy(plotter, point)` gives a 3D point's pixel, and `clip.at(x, y)` turns that pixel into a scene point for a label or a path.

To show an inside, cut a **volume** mesh (from a scan or a simulation) with `mesh.clip(normal=..., origin=...)`, and move `origin` over time to slice it open on screen. A model downloaded as a surface is hollow when cut. [Inside the heart](gallery/heart.md) does exactly this with a CT-derived heart.

## Cut it open: `Cutaway`

`Cutaway` does the cutting, colouring, camera and labelling for you, for any scan, CAD part or simulation. Give it a mesh (or a file PyVista reads) and where to cut:

```python
from manimvox.scenes import Cutaway

# a round part: cut a quarter away along its axle, seen from three-quarters
cut = Cutaway("research/assets/bearing.stl", axis="x", towards=(0, -1, 0), regions="part")
spin = cut.turning(6, zoom=1.2)     # the part turning about its own axle
sweep = cut.sweep(2.4, zoom=1.2)    # the quarter being cut away
opened = cut.opened(zoom=1.2)       # the same camera, looking into the cut

labels = leaders(cut.labelled(opened, {"Roller": cut.region_centre(3)}), side="right")
```

- **Where to cut.** `plane="x"`, `"-y"`, a normal or `(origin, normal)` for one flat cut, which suits a scan with a natural plane, like the heart's four chambers. `axis=` removes a 90° wedge instead, which suits anything round, such as a bearing, a pipe or an engine.
- **Colour.** `regions=` names an array that labels the parts, with `colours=` for their colours; `field=` colours a simulation by a value such as stress or temperature, and `extreme()` finds its peak on the cut. `colour(...)` recolours later shots, so the part being named can take the accent.
- **One camera.** `turning`, `sweep` and `opened` share `turn`, `zoom`, `lift` and `aim`, so the viewer never loses their place; `move()` glides between two views.
- **Labels.** `region_centre(value)` finds a part on the cut face, and `labelled(clip, {...})` turns 3D points into the points `leaders` needs.

[What lets a loaded wheel turn so freely?](gallery/tapered-bearing.md) uses a quarter cut on a real bearing; [Inside the heart](gallery/heart.md) uses one plane on a CT scan.

## Where it runs

`from_model` and `from_pyvista` need OpenGL 3.2: a graphics driver on a desktop, `sudo apt install libegl1 libosmesa6` on a Linux server with no display, or Mesa's software `opengl32.dll` on a Windows server. Without it, they stop with a message naming the fix. CI runs these tests on all three systems.

## Licences

A model or scan from the web has a licence: check that it allows your use, put its credit on screen, and record it in `FACTS.md`.

`manimvox assets add <url>` does this for you. It asks before downloading, saves the file under `research/assets/`, records the source, licence and credit line in `research/assets.json` and under `## Assets` in `FACTS.md`, and refuses a licence that does not allow the use.

```bash
manimvox assets add https://zenodo.org/records/4590294/files/18.tar.gz
manimvox assets add https://example.org/heart.stl --licence CC-BY-4.0 --credit "A. Author, Heart model, example.org"
manimvox assets list
```

For a Zenodo record or a Wikimedia Commons file page the licence, authors, title and checksum come from the source; any other URL needs `--licence`. Public domain, CC0, CC BY, CC BY-SA and open-source or open-data licences (MIT, BSD, Apache-2.0, ISC, ODC-By, ODbL, PDDL, OGL) are accepted. A no-derivatives licence is always refused, because cutting, simplifying or recolouring a model is a derivative. A non-commercial licence is refused unless you pass `--non-commercial`, and then `FACTS.md` notes that the video must not be used commercially. Archives are saved as downloaded, not extracted. Show the recorded credit line on screen.
